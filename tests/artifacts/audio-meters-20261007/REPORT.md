# تنفيذ مؤشرات الصوت والميكروفون — 2026-10-07

تم تنفيذ المؤشرات ضمن لوحة الإنتاج الحالية مع المحافظة على Vanilla JS / Native Web Components وعدم إضافة تبعيات أو تسجيل الصوت.

## السلوك

- مؤشر حي بجانب نسبة ضبط Mic وMaster في الواجهة الأمامية لجميع الثيمات العشرة.
- تفاصيل الصوت تتضمن مؤشرات الميكروفون والاستماع والبث، واسم الجهاز الحقيقي، وحالة الإشارة، واختيار الأصلي أو جهاز Sonar للميكروفون. البث يظهر في وضع Streamer فقط.
- النسبة هي ضبط Sonar، والشريط ذروة endpoint مقاسة من Windows، بمقياس لوغاريتمي من -60 إلى 0 dBFS. تختلف النسبة عن قوة الإشارة؛ القراءة قبل تحكم Windows بمستوى الجهاز لا تثبت وحدها حالة الكتم.
- هجوم 20ms، هبوط 180ms، تثبيت الذروة 900ms، تحديث الرسم بـ dt، وألوان دلالية عند -6 و-1 dBFS.
- الصفر قراءة صحيحة للصمت، والمفقود/القديم غير متاح؛ لا توليد لموجات وهمية ولا احتفاظ بالقيم عند انتهاء صلاحيتها.
- يوقف العنصر rAF عند الخفاء/قلب البطاقة، ويفك الاشتراكات والمراقبين عند الإزالة. النصوص تتغير فقط عند اختلافها، وقيم قارئ الشاشة تتحدث كل 200ms.
- حفظ اختيار مصدر الميكروفون محليًا. لا تعديل لمستويات Sonar أو Windows أو أي إعداد صوت فعلي.

## المصدر الفعلي

اكتشاف Sonar عبر CoreProps الموجود، ثم /audioDevices و/streamRedirections أو /classicRedirections، مع فحص active/isRunning واتجاه الجهاز. لا استخدام لجهاز Windows الافتراضي بدل وجهة Sonar ولا تخمين لوجهات Classic المختلفة.

- الأصلي: Desktop Microphone (RØDE PodMic USB).
- الميكروفون الافتراضي: SteelSeries Sonar - Microphone.
- الاستماع: Headphones (Arctis Nova Pro Wireless).
- البث: SteelSeries Sonar - Stream (وجهة render المحددة في Sonar).

أعاد جهاز Sonar Microphone صفرًا في جلسة التحقق، بينما أعاد الأصلي إشارة متغيرة. هذا يؤكد قراءة endpoint للصفر، ولا يثبت التقاط كلام بعد المعالجة. الافتراضي هو الميكروفون الأصلي، والخيار الآخر واضح دون استبدال صامت. لم نفتح جلسة تسجيل أو نغير إعدادات المستخدم لاختبار ذلك.

## النقل وحماية البيانات

- خدمة ctypes على thread واحد يملك كائنات COM ويحررها، وسحب مستهدف 30Hz.
- أحداث audio-levels مستقلة عن state-changed؛ لا إعادة رسم بطاقات العتاد مع كل عينة.
- الاشتراك برسائل الصوت عبر WebSocket اختياري وصريح للواجهة الجديدة، حتى لا تعتبرها النسخ المخزنة القديمة لقطة عتاد كاملة.
- قفل إرسال لكل اتصال، إرسال متوازٍ للعملاء، مهلة 250ms لمنع تعليق الجميع خلف عميل بطيء، وجدولة بالمواعيد المطلقة لتجنب تراكم تقريب مؤقت Windows.
- HTTP fallback عبر /api/audio-levels بمعدل polling الحالي. انتهاء عينة الباكند 500ms، انتهاء توجيه Sonar بعد 2s، مهلة عرض WS 300ms أو polling 1200ms. الانقطاع العام يمسح المؤشرات أيضًا.

## التحقق

- 55 اختبار Python ناجحًا (الصوت، Sonar، صدق القياس، AIDA، API، المباريات، التحديث، الأداء). تحذيرات deprecation موجودة من المكتبات القديمة، دون أخطاء اختبار.
- 18 فحصًا سلوكيًا للواجهة ناجحًا، مع اختبارات الثيمات الثلاثة والإدراج وخريطة البيانات الكاملة.
- فحص syntax لجميع 22 وحدة JS في frontend/js وملفات Python في backend ناجح.
- التحقق الحي من مصادر الصوت، المصدر الأصلي/الافتراضي، عدم قلب البطاقة عند الاختيار، وفتح/إغلاق تفاصيل التصميم الجديد.
- فحص 1920×1080 لكل الثيمات؛ النتائج والأداء في browser-verification.json. صور أورورا الأمامية والخلفية، وصور Orbit وVector وFolio من البيانات الفعلية مرفقة في هذا المجلد.

- استقبلنا 140 عينة صوت و10 لقطات عتاد خلال 5.039 ثانية؛ نحو 27.8Hz فعليًا تحت الحمل الحالي، والفاصل الوسيط 31.06ms. مصدر الخدمة يستهدف 30Hz؛ لا ندّعي معدلًا مضمونًا تحت كل الأحمال. النسخة القديمة تلقت العتاد فقط.
- اختبار COM حي: 8000 قراءة عبر 20 دورة فتح وإغلاق؛ عدد مقابض العملية 231 قبل و231 بعد (delta = 0).

قياس rAF هو أداء رسم المتصفح، مستقل عن FPS اللعبة المعروض من AIDA64. القياس فترة قصيرة في الجهاز الحالي؛ راجع الفواصل القصوى وp95 داخل ملف النتائج، وليس متوسط FPS فقط.

النسخة الاحتياطية قبل التعديل: backups/audio-meters-20261007. خدمة localhost:8088 أعيد تشغيلها وتحمل الكود الجديد. يمكن إعادة تحميل شاشة المستخدم لإحضار الأصول الجديدة.

مرجع تفسير نقطة قياس Windows: [Microsoft Core Audio Peak Meters](https://learn.microsoft.com/en-us/windows/win32/coreaudio/peak-meters).

نتيجة فحص الثيمات العشرة: لا تجاوز أفقي للقنوات ولا تمرير عام خارج viewport؛ لا أخطاء أو تحذيرات متصفح بعد تحميل النسخة النهائية. أعلى p95 لفاصل rAF = 16.6ms، ولا مهام longtask أثناء نوافذ القياس. أعلى فاصل مفرد = 37.5ms؛ لذلك لا نساوي نجاح p95 بعدم وجود أي إطار متأخر.
