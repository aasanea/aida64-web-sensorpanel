# تدقيق Sonar في Aurora — 2026-10-06

النتيجة: اتصال Sonar حقيقي والتحويل من 0–1 إلى نسبة مئوية صحيح، لكن اللوحة تقرأ وضع Classic رغم أن الوضع النشط هو Streamer. لذلك القيم الحالية لا تصف المكسر الذي يستخدمه المستخدم.

تم فحص عملية SteelSeriesSonar.exe، واجهة GG الأصلية، API الخاص بالبرنامج، API لوحة البيانات، ووجهي بطاقة Aurora. لم تُغيّر إعدادات الصوت أو ملفات التطبيق.

## المقارنة المباشرة

واجهة Sonar `/mode` أعادت `stream`. القيم أدناه محفوظة في `live-comparison.json`؛ ومقارنة واجهة البرنامج الأصلية أكدت مستويات الاستماع والبث.

| القناة | لوحة البيانات | الاستماع Monitoring | البث Streaming |
|---|---:|---:|---:|
| Master | 0% | 12% | 100% |
| Game | 100% | 12% | 100% |
| Chat | 100% | 12% | 100% |
| Media | 100% | 12% | 30% |
| Aux | 100% | 12% | 100% |
| Mic | 100% في API، حالة الكتم فقط في واجهة Aurora | 100% | 100% |

Aux موجود في API رغم أن واجهة المكسر الحالية تعرض زر Add aux channel. وجود مستوى محفوظ له لا يثبت أن القناة مضافة أو موجهة حاليًا.

كل حالات muted أعادت false في Classic وفي مساري Streamer. عبارة الميكروفون مباشر تعكس عدم الكتم، ولا تقيس وجود صوت أو مستواه اللحظي. رمز Master المكتوم ينتج أيضًا عن وصول المستوى إلى صفر؛ ليس دليلًا على تفعيل زر Mute.

## السبب في المصدر

- `backend/services/sonar_service.py:129`: يستخدم `/volumeSettings/classic` دائمًا، دون قراءة `/mode` أو اختيار `/volumeSettings/streamer`.
- `frontend/js/components/dashboard-display.js:1549`: يحترم Master=0، لكنه يستخدم مستوى Windows بديلًا إذا غاب Master، دون تغيير تسمية Sonar.
- `backend/services/sonar_service.py:132` و`:193`: عند فشل Sonar يُغيّر علم الاتصال فقط، ويحتفظ بالمستويات وحالة الميكروفون السابقة. تحقق اختبار معزول من ذلك دون إيقاف برنامج المستخدم.
- `frontend/js/components/dashboard-display.js:1202` و`:1265–1299`: أوصاف 7.1 و360° و96kHz، أسماء EQ، السماعة، وحالة Spatial Audio نصوص ثابتة، وليست قراءات من Sonar. بعض القسم موسوم غير مقاس، لكن عبارات نشطة ومفعّل ما زالت توحي بالحالة الفعلية.
- بروفايل Game الحقيقي وقت الفحص هو Hell Let Loose: Vietnam؛ Chat هو Custom؛ Media هو Music: Reggae. لا تطابق الأسماء الثابتة المعروضة خلف بطاقة Aurora.
- أعمدة الطيف تتحرك بواسطة CSS، ولا تعتمد على عينات الصوت أو Peak/RMS.

## التصحيح المطلوب

1. قراءة وضع Sonar النشط واختيار مصدر المستويات وفقه. في Streamer يجب عرض الاستماع والبث منفصلين وبأسماء واضحة، بما فيها mute لكل مسار.
2. إظهار القراءة غير المتاحة عند فشل Sonar، وإزالة القيم القديمة وحالة الميكروفون السابقة. فصل مستوى Windows عن مستوى Sonar.
3. قراءة البروفايلات والميزات من مصدر فعلي أو عرضها غير متاحة؛ إزالة أي ادعاء ثابت بأنها نشطة. فصل المؤثر البصري عن قياس الصوت الحقيقي.
4. إضافة حالات اختبار لـ Streamer، التبديل بين الوضعين، وفشل Sonar مع استمرار بيانات العتاد.

اختبارات Sonar الحالية الأربعة نجحت، لكنها تختبر Classic فقط. لم يُجر اختبار تغيير منزلقات الصوت أو كتمها، حفاظًا على إعدادات المستخدم أثناء التدقيق.
